3. Формула Score
Расчёт идёт по шагам:
Новое значение показателя. Для каждого района d и показателя k: I'_dk = clip(I_dk + Σ эффект_m,k × (8 − L_m)/8 + синергии, 0, 100)
Оценка района. D_d = Σ w_k × I'_dk. Веса показателей:

Сумма весов = 1. По направлениям веса такие: транспорт 0.20, экология 0.20, соцсфера 0.22, безопасность 0.18, сервисы 0.20.
3. Городской балл. D_avg = Σ pop_d × D_d (средневзвешенный по населению).
4. Итоговый Score.
Score = 0.7 × D_avg + 0.3 × min(D_d) − 1.0 × N_crit
Здесь N_crit = число пар «район × показатель» со значением строго меньше 40 после всех эффектов. Штраф 1 балл за каждую.
Смысл формулы: 70% веса идёт на общий результат по городу, 30% на самый слабый район, чтобы нельзя было «вылизать» один район и забыть про Нуру. Штраф за критические значения не даёт оставить провалы.
Базовый Score без действий: 52.56
(0.7 × 56.86 + 0.3 × 49.18 − 2, где два критических значения это S1 и S2 в Нуре.)

Роль ИИ: LLM получает результат расчёта (дельты по районам и показателям, вклад каждой меры) и объясняет его, сравнивает наборы, советует. Числа он не считает и не придумывает.

4. Правила
Бюджет: 100 условных единиц. Остаток не сгорает и не даёт бонуса.
Решений ровно 5, не «до 5».
Повторы запрещены. Каждое мероприятие максимум один раз.
Район: для мер типа «Район» он указывается обязательно, для мер типа «Город» не указывается.
Не более 2 мер из одного направления. Из этого автоматически следует, что затронуто минимум 3 направления.
Несовместимости из раздела 2 запрещены.
Невалидный набор (нарушено любое правило) получает Score = не считается, валидатор возвращает причину.
Порядок решений значения не имеет.
Существование допустимого решения: пример из раздела 3 валиден (95 ≤ 100, 5 мер, нет повторов, по направлениям 2/1/1/1, конфликтов нет). Самый дешёвый набор M9 + M11 + M10 + M12 + M4 стоит 61 и тоже валиден.
