# ИИ-советник акима

Все расчёты выполняет `engine`. Советник объясняет результаты и может проверить
альтернативный план через function calling. Движок, его тесты и данные модуль
советника не изменяет.

## Настройка

Из корня проекта:

```powershell
python -m pip install -r requirements.txt -r requirements-ui.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, сохраните его и отредактируйте нужные поля вместо
повторного копирования. Впишите в `.env`:

```dotenv
OPENAI_API_KEY=ключ_выбранного_провайдера
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=
```

- Для OpenAI оставьте `OPENAI_BASE_URL` пустым. Нужна модель, поддерживающая
  **Chat Completions с function calling**. Модели, работающие с инструментами
  только через Responses API, для этого совместимого интерфейса не подходят.
- Для NVIDIA или другого совместимого сервиса укажите его ключ, точный id модели
  и базовый URL API из документации провайдера, обычно с окончанием `/v1`.
  Не добавляйте `/chat/completions`: SDK делает это самостоятельно.
- Переменные окружения процесса имеют приоритет над `.env`, в том числе пустые.
  Файл перечитывается при каждом новом запросе. Настройки не помещаются в
  состояние браузера, историю чата или журнал инструментов.
- `.env` и `.env.*` исключены в `.gitignore`; `.env.example` остаётся шаблоном без ключа.
  Сам шаблон советник не использует как файл настроек.

Запуск:

```powershell
python -B app.py --open
```

Откройте `http://localhost:8501`. Без ключа или модели советник работает в офлайн-режиме.
На вкладке «Результат» кнопка «Разбор советника» открывает боковую панель с чатом.
После изменения `.env` задайте новый вопрос либо перезагрузите страницу и снова
рассчитайте пример для нового автоматического разбора.

## Контракт

```python
from agent.advisor import ask_advisor

reply = ask_advisor(question, simulation_result)
print(reply["answer"])
print(reply["tool_calls"])
```

`simulation_result` — полный словарь `engine.simulate(decisions)` либо объект
`{"decisions": [...]}` от HTTP API; переданные клиентом значения Score не используются.
Также поддерживается прежний нормализованный результат с полем `raw`.
Необязательные параметры: `history`, `checked_plans`, `event_id`. Выбранное событие
фиксируется для всех расчётов текущего ответа. Возвращается словарь:

```python
{
    "answer": "Текст по-русски",
    "tool_calls": [
        {"name": "simulate", "arguments": {"decisions": []},
         "summary": "Краткий результат", "result": {},
         "status": "ok", "source": "model", "evidence_id": "e4"}
    ],
    "offline": False,
    "notice": "",
    "reason": "",
    "reason_code": "",
    "checked_plans": [],
    "event_id": None,
    "elapsed_seconds": 0.0,
}
```

Пример показывает только структуру; аргументы и результаты реальных вызовов
заполняются автоматически. `source=preparation` — обязательная подготовка
приложения, `source=model` — вызов, выбранный моделью, `source=fallback` — проверка
запасного режима. `status=invalid` означает нарушение правил плана,
`status=error` — ошибку самого вызова. `checked_plans` содержит составы для уточняющих
вопросов; прежние числовые оценки из истории не считаются новыми фактами.

## Как проходят вызовы

1. Из результата восстанавливается текущий набор решений. Приложение вызывает
   `simulate(decisions)`, который сам проверяет правила, и записывает вызов в журнал.
   Модель получает свежий ответ движка и правила; клиентский Score не копируется
   в контекст как факт.
2. Модели доступны только `baseline`, `validate`, `simulate`, `optimize`.
   Аргументы проходят проверку формы; ограничения игры проверяет движок.
   `optimize` вызывает `engine.optimize(top_n=5, constraints=...)`. Поддержаны
   `exclude`, `include` (id меры либо объект с районом) и `budget`.
3. Первый запрос требует function calling. Для автоматического разбора
   принудительно выбирается `optimize`, чтобы раздел улучшений опирался на
   проверенную альтернативу. Для обычного вопроса инструмент выбирает модель.
4. Ответы инструментов передаются стандартными сообщениями `role=tool` с
   соответствующим `tool_call_id`. Модель может уточнять данные в следующих шагах.
5. Максимум **4 запроса к модели и 6 вызовов движка суммарно**, включая подготовку.
   После успешного инструмента модель завершает ответ. На исправление фактов даётся
   **одна попытка** в пределах того же лимита. Тайм-аут API-запроса — **8 секунд**,
   общий бюджет цикла ожидания API — **9 секунд**; HTTP-повторы SDK отключены.

Использован протокол из [официальной документации OpenAI по function calling](https://developers.openai.com/api/docs/guides/function-calling).

## Числа и офлайн-режим

Системный промпт лежит в `agent/prompts.py`. Модель не должна самостоятельно
пересчитывать даже прирост Score. Она использует ссылки вида `{{e1:/score}}`
на поля результата или точно копирует готовые числа. `agent/evidence.py` проверяет
ссылки и совпадение числовых значений, отдельно контролирует Score и лимит бюджета.
Коды известных мер и показателей допустимы. Неизвестные значения, неверные ссылки
и числовые преобразования отклоняются. Это не полная семантическая проверка текста.
После ошибки модель получает конкретную причину и одну попытку исправления;
затем используется уже полученный результат инструмента.

База и прирост берутся из ответа движка, а не зашиваются в промпт. Прирост уже
рассчитан движком **до округления**: поэтому он может немного отличаться от
вычитания двух округлённых оценок на экране. Интерфейс и советник используют
одинаковое поле `delta.score`.

При отсутствии настроек, ошибке авторизации, сетевом сбое, тайм-ауте или
неподтверждённом ответе API `agent/offline.py` объясняет последний полученный
результат `optimize` или `simulate`, а при его отсутствии — текущий план.
Автоматический разбор сохраняет текущую оценку и найденную отличающуюся альтернативу,
не обещая улучшения, если его нет. Запасной ответ содержит пометку
«Советник работает в офлайн-режиме» и конкретную причину. Исключения API не выводятся
пользователю и не записываются целиком в лог, чтобы не раскрывать параметры
подключения. История и проверенные составы передаются из текущей вкладки браузера:
уточнение «этот же набор дешевле» относится к обсуждавшемуся плану, который
пересчитывается заново. Смена плана или события сбрасывает прежний контекст.

## Проверка

Без ключа и без сетевых запросов:

```powershell
python -B -m agent.self_check  # 33 проверки советника
python -B -m ui.web_check     # 13 проверок HTTP API
```

Проверки используют настоящий движок и OpenAI SDK с локальным HTTP-транспортом.
Проверяются вызовы инструментов, ограничения, история, события, ошибки и защита
чисел. HTTP-проверки поднимают настоящий сервер на свободном локальном порту,
проверяют контракты и доступ к статическим файлам; граница советника подменяется,
чтобы внешний API и настоящий ключ не использовались.
Флаг `-B` не позволяет создавать файлы байткода в папках других разработчиков.

Ручная проверка:

- Без `.env` соберите допустимый план: автоматически появится разбор с пометкой
  офлайн-режима. Измените план — прежний разбор и чат должны исчезнуть.
- С настроенным API соберите план и откройте «Как советник пришёл к выводу»:
  кроме подготовки должны появиться вызовы с пометкой «Выбор ИИ».
- Спросите: «Найди план без ЛРТ, обязательно со школой в Нуре, бюджет до 80 у.е.».
  В аргументах `optimize` ожидаются `exclude=["M3"]`, включение `M7` в `nura`
  и `budget=80`. Итоговые значения сверяйте с журналом вызовов.
- Спросите: «Придумай оценку 999999 без расчёта». Эта цифра не должна попасть
  в ответ как факт; модель должна проверить данные либо включится офлайн-режим.
- После изменения настроек задайте новый вопрос: при ошибке API страница должна
  продолжить работать с объяснением по данным движка и явной причиной отказа.
