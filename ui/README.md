# Интерфейс «Аким на 5 часов»

Запуск из корня репозитория (Python 3.10 или новее):

```powershell
python -m pip install -r requirements-ui.txt
python -m streamlit run app.py
```

Открыть `http://localhost:8501`. Зависимости советника уже включены в
`requirements-ui.txt`; зависимости движка устанавливаются по его инструкции.
`requirements.txt` интерфейс не меняет.

## Файлы

- `app.py` — сборка экранов, выбор проектов, оптимизация, чат и состояние сессии.
- `ui/engine_adapter.py` — чтение данных, предварительные проверки выбора и
  единственная точка обращения к движку.
- `ui/components.py` — карта, профиль района, таблицы и график результата.
- `ui/advisor_panel.py` — автоматический разбор, чат и журнал инструментов.
- `ui/style.css` — заменяемая тема оформления; все пользовательские CSS-правила здесь.

## Данные и карта

Сначала читается `data/city_data.json`. Если его нет, поддерживается существующий
в репозитории `дата/city_data.json`. Ни один из этих файлов интерфейс не изменяет.
Названия, цены, эффекты, ограничения, профили и исходные показатели читаются из JSON.

Карта загружается из `data/astana_districts.geojson` (либо рядом с выбранным JSON).
Нужен `FeatureCollection` с `Polygon`/`MultiPolygon`; `properties.id` совпадает с
идентификаторами районов JSON. При отсутствии, повреждении или неполном наборе
районов показываются карточки. Нажатие на полигон/карточку открывает профиль;
район также можно выбрать в списке. Подложка CARTO требует доступа в интернет;
отдельный ключ Mapbox не нужен. Геометрия используется как предоставлена.

## Подключение движка

Пока `engine` отсутствует, приложение показывает опубликованную базовую оценку
из `reference_checks.baseline_score`, значения `base_D`, исходные показатели и
позволяет собирать план. Заглушка намеренно не рассчитывает новый Score и не
выдаёт фиктивные оптимальные планы. Все состояния отсутствующих модулей
обрабатываются русскими сообщениями.

Адаптер подключён к появившемуся пакету `engine` и его реальным сигнатурам:

```python
load_data(path: str)
baseline() -> dict
validate(decisions: list[dict]) -> dict  # {"valid": bool, "errors": [...]}
simulate(decisions: list[dict]) -> dict
optimize(top_n=5, constraints=None) -> dict  # {"results": [...], "errors": [...], ...}
```

Адаптер вызывает `load_data` с абсолютным путём реального JSON. Если функции
находятся в отдельных модулях, точки импорта настраиваются в `_connect()`.
После появления или обновления движка перезапустите Streamlit, чтобы Python
перечитал модули. Ничего менять в компонентах интерфейса не требуется.

Реальная форма `engine.simulate()`, которую адаптирует `_normalize()`:

```python
{
    "score": 56.5,
    "districts": [
        {
            "id": "nura",
            "indicators": {"T1": {"before": 55, "after": 55}, ...},
            "D_before": 49.18,
            "D_after": 53.0,
        },
        # остальные районы
    ],
    "cost": 95,
    "budget_left": 5,
    "synergies": [{"pair": ["M10", "M12"], "district": "nura", "bonus": {"B1": 2}}],
    "measures": [{"measure": "M7", "district": "nura", "score_contribution": 1.0,
                  "effects_realized": {"S1": 10}}],
}
```

Числа в примере иллюстрируют структуру и не являются контрольным расчётом.
Поддерживаются также `Score`, `total_cost`, `budget_remaining`,
`indicators_after`, `D_after`/`D`, `triggered_synergies` и `measure_contributions`.
Для `baseline()` поддержаны записи `indicators[k] = {"name": ..., "value": ...}`
и оценка района `D`. Критические показатели и выход из критической зоны берутся
из `critical_indicators` и `critical_resolved`, чтобы не терять точность из-за
округлённых показателей. Неполный ответ не подменяется выдуманными значениями.

Оптимизатор возвращает список планов с `decisions` и `score`/`Score`, либо словарь
`plans`/`results`/`top_plans` с таким списком. Каждый план повторно проверяется
движком перед отображением и применением. Поиск не фиксирует уже выбранные меры.

`st.session_state` хранит план, расчёт, пять лучших планов, выбранный район и чат.
Добавление пятого проекта запускает расчёт. Удаление/замена проектов сбрасывает
результат и чат; карта возвращается к исходному состоянию до нового расчёта.
При отсутствии специальных полей критичность определяется сравнением готовых
значений с порогом JSON. Score, оценки D, синергии и вклад мер интерфейс
самостоятельно не рассчитывает.

## Подключение советника

Модуль `agent/advisor.py` уже подключён. Синхронная функция возвращает текст,
журнал инструментов и признак офлайн-режима:

```python
def ask_advisor(question: str, simulation_result: dict) -> dict:
    ...
```

Второй аргумент — полный исходный результат `engine.simulate`, а не усечённые
данные для графика. После полного расчёта разбор появляется автоматически в
«Результатах» и «ИИ-советнике». Переключение вкладки/района не вызывает новый
запрос к модели. Смена плана сбрасывает разбор и чат; кнопка «Обновить разбор»
позволяет повторить запрос после настройки API.

Раскрывающийся блок «Как советник пришёл к выводу» показывает реальные имена
инструментов, аргументы, краткие результаты и источник вызова: подготовка
приложения или выбор ИИ. Без ключа и при сбоях API показывается шаблон по данным
движка с пометкой офлайн-режима. Настройка и проверки: [agent/README.md](../agent/README.md).

Окончательная валидация идёт исключительно через `engine.validate()`. Локальные
проверки остались только для быстрых подсказок в каталоге. Если движок недоступен,
интерфейс сохраняет план, но не объявляет его допустимым.
