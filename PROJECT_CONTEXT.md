# «Аким на 5 часов»: контекст проекта для нового чата

Снимок рабочего проекта от **23 сентября 2026 года, после доработки для релиза**. Документ предназначен владельцу проекта и следующему ИИ-помощнику. Его можно прикрепить в новый чат. После новых изменений исходники имеют приоритет над этим снимком.

**Главные изменения релиза:** настоящие полигоны OpenStreetMap для шести районов; Сарайшык показан без выдуманных показателей; расчётный датасет ТЗ по-прежнему содержит пять районов. Планы и чат восстанавливаются после F5, есть сохранённые команды, безопасный JSON-импорт/экспорт, сравнение и печатная презентация. Числовые утверждения советника формирует код из результата движка, модель добавляет качественный комментарий. Проверены 112 тестов движка + 52 проверки советника/API, отдельная чистая установка и шесть живых вопросов ИИ.

Сценарий защиты, таблица живых запросов и список материалов для автора README: [docs/RELEASE_NOTES.md](docs/RELEASE_NOTES.md). Снимки интерфейса находятся в `docs/screenshots/`.

Мы делаем хакатонный AI-симулятор управления Астаной. Пользователь хочет обсуждать весь проект с одним основным помощником. Сначала прочитай этот файл, затем актуальные исходники нужного модуля и оба файла ТЗ в `docs/tz/`.

- **Не выполнять Git-команды:** коммитами и публикацией занимается пользователь.
- **README сейчас пишет другой программист.** Не перезаписывать `README.md` и не терять его параллельные изменения.
- До этого интерфейс и советник разрабатывались отдельно от `engine/`, `tests/`, `data/`, `requirements.txt`. Эти части не меняли при интеграции дизайна. Не переписывать их без конкретной новой задачи; сохранять разделение работы.
- Все расчётные числа должны происходить из `engine/` или `data/`. Браузер и LLM не реализуют свою формулу Score.
- Не менять исходный датасет, ограничения или эталонные числа ради красивой демонстрации.
- Не читать и не печатать API-ключ для диагностики. Не переносить `.env` в браузер, документацию, ответы API или журнал инструментов.
- **Основной интерфейс уже не Streamlit.** Это HTML/CSS/JavaScript и локальный Python HTTP API. React и npm-сборки нет.
- Старый Streamlit находится в `legacy/`. Не возвращать его в основной запуск и не подключать новый дизайн как iframe старого приложения.
- Проверять существующие функции прежде, чем предлагать их написать: оптимизация, события, устойчивость, сравнение и живой советник уже реализованы.

## 2. Что делает продукт

Игрок выступает в роли акима Астаны и выбирает **ровно 5 разных проектов из 14** при бюджете **100 условных единиц**. Районные проекты размещаются в одном из пяти районов; городские действуют во всех районах. Движок проверяет допустимость и рассчитывает Astana Quality of Life Score на горизонте **8 кварталов**.

Продукт показывает показатели до/после, слабые районы, критические значения, синергии и вклад мер. Советник объясняет сильные стороны, риски, последствия и проверяет альтернативы через инструменты. Дополнительно есть полный перебор лучших планов, восемь кризисных событий, поиск устойчивого плана и сравнение.

Это **учебная сценарная модель на датасете ТЗ**, а не подтверждённый прогноз реального городского бюджета. Использование синтетических данных прямо разрешено ТЗ. Название «на 5 часов» — название игры, а расчётный горизонт модели составляет 8 кварталов.

Пять направлений: транспорт, экология, соцсфера, безопасность, сервисы. **Не требуется выбирать по одному проекту каждого направления.** Подробные правила разрешают максимум два проекта одного направления, значит полный план охватывает минимум три направления. Пример ТЗ охватывает четыре, лучший обычный план — три.

Ограничения:

- Ровно 5 решений, повторы меры запрещены даже в разных районах.
- Стоимость не выше текущего бюджета. Остаток не даёт бонуса.
- Для районной меры обязателен район; для городской нужен `district: null`.
- Не более 2 мер одного направления.
- M1 + M3 запрещены в любом размещении.
- M4 + M7 запрещены **в одном** районе, в разных допустимы.
- M5 + M13 запрещены **в одном** районе, в разных допустимы.
- Порядок решений не влияет на результат.
- При любом нарушении Score не рассчитывается: `valid: false`, `score: null`, причины в `errors`.

Синергии фиксированы и лагом не масштабируются: M1+M2 → T1 +2 в районе M1; M10+M12 → B1 +2 в районе M10; M5+M6 → E2 +2 в районе M5.

## 5. Математика и важные нюансы

```text
H = 8
I'[d,k] = clip(I[d,k] + Σ(effect[m,k] × (H − lag[m]) / H) + synergy[d,k], 0, 100)
D[d] = Σ(weight[k] × I'[d,k])
D_avg = Σ(population_share[d] × D[d])
N_crit = число пар (район, показатель), где I'[d,k] < 40
Score = 0.7 × D_avg + 0.3 × min(D) − N_crit
```

Реализация: `engine/model.py`, общий `score_parts()` используется расчётом и оптимизатором. Коэффициенты приходят из данных.

**Округление:** точная база 52.55768, пример 56.54307. В интерфейсе это 52.56 и 56.54, но точная разница округляется до **3.99**, а не 3.98. Брать `delta.score`, `score_delta`, `D_delta` из ответа движка. Не вычитать уже округлённые значения.

**Вклады неаддитивны:** вклад меры считается сравнением с планом без этой меры, включая изменение синергий. Для примера сумма вкладов 4.06, тогда как общий прирост 3.99. Это следствие взаимодействий, минимума района и штрафов, а не ошибка суммирования. Не изображать вклады точным разложением общего прироста.

**Нура важна** из-за минимальной районной D и исходных критических S1/S2. Формула поощряет поднятие слабейшего района, а не только улучшение самого благополучного.

## 8. Публичный API движка и HTTP

Основные Python-функции:

```python
load_data(path=None, events_path=None)
baseline(data=None, event_id=None)
validate(decisions, data=None, event_id=None)
simulate(decisions, data=None, event_id=None)
optimize(top_n=10, constraints=None, data=None, event_id=None,
         robust=False, robust_events=None)
list_events(data=None)
robustness(decisions, events=None, data=None)
compare(plans, event_id=None, data=None)
```

`constraints` оптимизатора поддерживает `exclude`, `include`, `budget`; `include` может закреплять меру или пару мера/район. `compare` принимает словарь `название → план`: значение может быть списком решений либо объектом с полем `decisions`, например элементом выдачи оптимизатора.

Ответ `simulate` содержит `valid`, `errors`, `score`, `baseline`, `delta`, `cost`, `budget`, `budget_left`, `districts`, `N_crit`, `critical_indicators`, `critical_resolved`, `critical_new`, `synergies`, `measures`, `min_district`. Районы содержат `D_before`, `D_after`, `D_delta` и показатели. У оптимизатора — `results`, `errors`, `constraints`, статистика и при необходимости данные устойчивости.

| HTTP | Назначение |
|---|---|
| `GET /api/health` | Проверка готовности |
| `GET /api/bootstrap?event_id=E1` | Каталог, база, GeoJSON, события; параметр необязателен |
| `GET /api/baseline`, `GET /api/events` | База и каталог событий |
| `POST /api/plan-status` | Стоимость/остаток неполного плана, validate, возможность выбрать пятую меру |
| `POST /api/validate`, `POST /api/simulate` | Проверка и расчёт; тело `decisions`, `event_id` |
| `POST /api/optimize` | `top_n` от 1 до 5, `constraints`, `event_id`, `robust` |
| `POST /api/robustness` | Устойчивость состава до событий |
| `POST /api/compare` | Именованные планы в одинаковом событии |
| `POST /api/advisor` | `question`, `decisions`, `event_id`, `history`, `checked_plans` |

Сервер не доверяет Score, присланному браузером. Советник получает состав и заново рассчитывает его. Статика раздаётся по белому списку: `.env`, `.git`, исходники и произвольные файлы через HTTP не выдаются. Сервер предназначен прежде всего для локального демо, не для публичного сервиса с пользователями и квотами.

Bootstrap дополнительно отдаёт `model_scope` (районы модели, географии и без показателей) и `geography` (источники, количество объектов, признак схематичной геометрии). География не расширяет модель автоматически.

## 9. Интерфейс и сохранённое поведение

- Полноэкранная карта Астаны; слева вкладки **Город / Проекты / Результат**.
- Score, база сравнения, дельта, текущий бюджет, остаток и счётчик проектов.
- Профиль района с десятью показателями; просмотр района отделён от выбора места проекта.
- У уже выбранной районной меры селектор заблокирован. Для смены района нужно убрать её и добавить заново.
- Быстрые подсказки блокируют заведомо недоступное добавление, окончательное решение принимает движок.
- После четырёх мер показано предупреждение, если допустимого пятого проекта нет.
- Полный план рассчитывается; карта переключается «Было / Стало», видны таблица и полосы по районам.
- Дельты приходят из движка. Промежуточной анимации вымышленных чисел Score нет.
- Есть критические показатели, синергии, эффекты и вклады мер.
- Кнопки поиска лучших планов, применения, устойчивости и сравнения текущего с лучшим.
- Кнопка **Событие** в шапке; **Демо-сценарий** ведёт по основным действиям.
- Авторазбор и чат находятся в боковой панели **Разбор советника**. Видны причина офлайн-режима и журнал инструментов.
- Повторный расчёт того же состава в тех же условиях не очищает чат и не вызывает советника снова.
- При смене плана или события старые запросы отменяются/отбрасываются по версии состояния.
- При недоступном API не подставляются числа из макета. При недоступной карте работают карточки районов.
- Тематический селектор карты показывает D или любой из десяти показателей; значения до/после берутся из движка. Серый район означает отсутствие показателей, а не нулевое качество жизни.
- «Риски и компромиссы» показывает районную разгрузку дорог и отрицательные прямые эффекты проектов с учётом лага. Это не прогноз пробок на конкретных улицах.
- «Планы команд» сохраняет именованные составы, импортирует/экспортирует JSON и сравнивает до десяти команд через `/api/compare`. Все команды сравниваются в одних выбранных условиях.
- «Отчёт» открывает внутри приложения краткую презентацию: состав и итог; районы и критические показатели; разбор и эффекты. Печать/PDF запускается отдельной кнопкой.

### География

GeoJSON — `FeatureCollection`. Свойство `features[].properties.id` совпадает с ID района. Также есть `name`, `name_full`, `source`, `osm_id`, `osm_names`, `area_km2`, `center_lon`, `center_lat`.

В текущем файле **шесть геометрий с `source: osm`**. Они собраны из исходных отношений OpenStreetMap без дорисовки и упрощения вершин. Все полигоны валидны, площадных пересечений между районами нет. Сарайшык имеет `scoring_enabled: false`. Добавлены `source_url`, `retrieved_at`, `osm_admin_level`, `geometry_status`; подробности и relation ID — в `docs/GEO_SOURCES.md`.

OSM — общественный картографический источник, не юридически заверенные границы. Геометрия скачана 23 сентября 2026 года, состояние источника — 22 сентября. `fetch_districts.py --offline` воспроизводит сохранённый настоящий ответ, а при ошибке обновления загрузчик оставляет предыдущий GeoJSON. Схематичной подмены больше нет. Карта использует внешние тайлы OpenFreeMap; MapLibre хранится локально. География не влияет на Score.

## 10. События и устойчивость

| ID | Событие | Область | Бюджет | Score базы при событии |
|---|---|---|---:|---:|
| E1 | Авария на магистральной теплосети | Алматы | 100 | 51.22 |
| E2 | Сильный буран | Весь город | 100 | 48.10 |
| E3 | Рост ДТП в межсезонье | Весь город | 100 | 50.64 |
| E4 | Прорыв водопровода | Байконур | 100 | 51.33 |
| E5 | Вспышка смога | Сарыарка | 100 | 51.33 |
| E6 | Сокращение бюджета | Весь город | 85 | 52.56 |
| E7 | Закрытие моста на капремонт | Есиль | 100 | 51.26 |
| E8 | Наплыв новосёлов | Нура | 100 | 50.89 |

Событие изменяет стартовые условия **до проектов**. База и дельта в отчёте относятся к выбранному событию, не всегда к обычной базе 52.56. Официальные контрольные числа ТЗ проверяются без события.

Лучший обычный план при E1 получает **55.90**. Остаётся один критический показатель: **C1 Алматы = 39.38**; минимальная D — **54.09 в Нуре**. Это не то же самое, что исходные проблемы города при E1 до проектов.

`robustness` рассматривает отдельные события от обычной базы; кризисы не накладываются друг на друга. Если план не проходит хотя бы одно событие, `worst_score` может быть `null`. При усреднении падения учитываются только сценарии с рассчитанным Score. Пример за 95 и обычный оптимум за 98 не проходят E6 с бюджетом 85.

`optimize(robust=True)` ищет максимальный Score в худшем событии. Такой поиск не совмещается с `event_id`; интерфейс отправляет для него `event_id: null`.

## 11. ИИ-советник

```python
ask_advisor(question, simulation_result, history=None,
            checked_plans=None, event_id=None) -> dict
```

Основные поля ответа: `answer`, `tool_calls`, `offline`, `notice`, `reason`, `reason_code`, `checked_plans`, `elapsed_seconds`, `event_id`.

Используется OpenAI SDK, **Chat Completions с function calling**. Настройки из `.env` с приоритетом переменных процесса:

```dotenv
OPENAI_API_KEY=<вписать свой ключ локально>
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=
```

Пустой BASE_URL выбирает OpenAI. Совместимый провайдер может использовать другой адрес и модель с поддержкой инструментов; совместимость конкретной модели нужно проверять. В шаблон и документацию настоящий ключ не добавлять.

Инструменты: `baseline`, `validate`, `simulate`, `optimize`, `list_events`, `robustness`, `compare`. Первые четыре и compare закреплены за событием приложения. `list_events` — справочник событий, `robustness` — отдельные сценарии до событий; область применения явно помечена.

Перед ответом выполняется подготовительный `simulate`, затем модель вызывает нужный инструмент. Обычно используются два запроса LLM. Лимиты: до **4 запросов модели**, до **6 инструментальных вызовов**, **8 с** на отдельное ожидание API и **9 с** на цикл ожидания API. Это не строгий предел всей функции с инициализацией и расчётами. Автоматические HTTP-повторы SDK отключены.

**Фактический и качественный слои разделены.** `offline.py` формирует проверенный фактический отчёт из нужного результата инструмента, включая текущий план, альтернативу, baseline или событие. LLM добавляет качественный комментарий; предложения с цифрами, числительными или ссылками на числа удаляются целиком и заменяются фактами движка. Нельзя вставить число бюджета под выдуманную подпись «стоимость». Если качественного текста не осталось, допускается **одна коррекция**, затем полезный fallback по уже полученному инструменту. `offline=False` означает, что реальный комментарий модели получен и включён в ответ.

Старые `render_grounded_answer` и JSON Pointer-утилиты сохранены для совместимости, но не являются проверкой публикуемого текста `ask_advisor`. Совпадение числа с любым числом в evidence само по себе не доказывает смысл фразы.

История — последние шесть реплик и последние проверенные составы. Уточнение про «этот же набор дешевле» проверяет последний обсуждавшийся состав, а не подменяет его текущим планом карты. Авторазбор ищет свободную отличающуюся альтернативу, не закрепляя все текущие меры.

Запросы о лишней мере/повышенном бюджете получают отказ и допустимую альтернативу. Вопросы об оставшихся рисках направляются в `simulate` текущего состава. Отсутствие ключа/модели, сбои API, тайм-ауты и отклонение текста не рушат приложение: есть объяснённый офлайн-режим.

**Ограничение:** качественная интерпретация LLM не является математическим доказательством и может быть спорной. Не обещать «галлюцинации математически невозможны». Расчётные факты и названия полей берёт код из выбранного результата. Вопрос про Сарайшык получает объяснение отсутствия показателей без выдуманного Score.

## 14. Известные слабые места: не путать с уже исправленными

### Исправлено в последней доработке

- Число из одного поля больше не публикуется под произвольной подписью LLM: существенные факты формируются кодом. Прежняя слабость старого `render_grounded_answer` не считается исправленной в самой совместимой утилите, но она исключена из пути публикации советника.
- Карточки устойчивого поиска постоянно подписаны «Score без события · база 52.56». Например, при E2 карточка показывает 56.83 / +4.27, а после применения расчёт в буране даёт 54.37 / +6.27; обе базы теперь явно названы.
- F5 сохраняет выбор и чат через `sessionStorage`, готовый разбор не вызывается заново после подтверждения свежим расчётом.
- Есть UI команд, проверенный импорт/экспорт и печатная презентация.
- Пять схематичных полигонов заменены шестью настоящими OSM-геометриями. Сарайшык не получает придуманных расчётных данных.
- Историческое описание дизайнера помечено как архив, генератор примеров обновлён. Есть lock-файл и доказанная чистая установка.

### Прочие ограничения

- Закрытие вкладки может удалить `sessionStorage`: для переноса состава используйте экспорт JSON. Совместной сетевой комнаты, аккаунтов и серверного хранения нет.
- Реальные эффекты мер и веса модели не откалиброваны на внешних наблюдениях; не обещать применение к реальному бюджету без такой работы.
- Сарайшык включён в географию, но отсутствует в модели ТЗ. Для шестирайонного расчёта нужен отдельно согласованный датасет с показателями и долями населения, отдельные эталоны и явное название режима.
- Уличной транспортной модели нет: тематическая карта показывает районные показатели, не текущий трафик или длину очередей. Нельзя заявлять предсказание конкретных заторов.
- OSM не является юридической гарантией границ. Полигон не подтверждает актуальность статистики датасета ТЗ.
- README продолжает писать другой программист; он должен согласовать окончательный текст с новыми возможностями и материалами.
- `docs/for_designer/DESIGN_BRIEF.md` описывает старый Streamlit; это исторический пакет, не текущий UI.
- В `agent/README.md` список инструментов местами ограничен прежними четырьмя; фактически доступны семь, перечисленных выше.
- Обычные launchers всё ещё устанавливают legacy-зависимости; облегчённый lock — отдельный способ установки. Linux/macOS/Docker в этой доработке не запускались.
- Выбор модели, сеть, квота и API влияют на живой текст. Офлайн-режим спасает демо, но шаблон не равен полноценному свободному диалогу LLM.

**Уже исправлено, не переносить в новый список ошибок:** лишний `/result/` в ссылках; широкие корни регулярных выражений; бесполезный общий fallback после найденной альтернативы; отсутствие истории; закрепление всех текущих мер при автооптимизации; сброс чата при повторном расчёте; несовпадение выбранного района с планом; пересчёт D_delta в UI; отсутствие объяснения офлайна; потеря event_id в инструментах; описание исходных рисков события вместо оставшихся после мер для соответствующего маршрута вопросов. Старые ошибки формата constraints оптимизатора также исправлены другим разработчиком.
